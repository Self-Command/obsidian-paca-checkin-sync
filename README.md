# Paca 任务同步

独立 Obsidian 插件，配合官方 TaskNotes、Paca 接入和打卡插件。支持桌面与手机；官方 TaskNotes 保持原版。插件 ID `obsidian-paca-checkin-sync` 保留，旧版设置与打卡记录可覆盖升级。

## 安装与配对

将成功 Release 安装 ZIP 中的 `main.js`、`manifest.json`、`styles.css` 放进笔记库 `.obsidian/plugins/obsidian-paca-checkin-sync/`，重新启用插件。在设置填写不带路径的 HTTPS 服务地址。设置只需一个配对码。覆盖升级会验证现有授权并自动迁移；保留设备身份、游标和待处理记录。新安装在 Paca 对应来源设置生成配对码。

Paca 和本插件设置中的打卡同步记录都支持彻底清理，待处理、已忽略及已归档记录均可处理。确认后删除服务器记录和照片，移除对应待处理项，保留已保存的本地笔记和附件。处理按钮保留设置页滚动位置及历史记录开关。

同一笔记库的电脑和手机可以使用同一个配对码。设备身份、游标、创建意图和离线队列分别保存；凭据不写入任务笔记、源码或发行产物。各设备仍需使用自己的笔记库同步工具，共享笔记与附件。

## 双向任务

先在 Paca 来源设置准备所选项目的全部任务清单，检查状态对应关系并确认首次同步，再启用本插件的双向任务同步。包括已完成、已归档任务；同名任务保持独立。Paca 页面、API 或 AI 创建的任务无需打卡，就会在下次拉取时创建官方 TaskNotes 笔记。

共享标题、内容、时间、状态、优先级、标签、归档及循环规则。官方事件产生的 Markdown 字段编辑也同步。任务完成、归档和删除通过官方 TaskNotes API；笔记缺失不自动重建。冲突可选择采用本地或服务器版本；未知创建结果先核对标记，不盲目再建。

循环母任务和每期任务使用服务器的统一关联；每期笔记通过官方循环 API 创建或复用，不产生第二套提醒。服务器继续执行最后确认的规则，关闭 Obsidian 不影响已确认的排期。客户端离线改动需联网补交后才影响服务器；完全未被记录的修改无法自动恢复。

## 打卡记录和照片

与任务同步分别启用。照片默认保存到独立的 `PushGo附件/`，不能与任务目录相同或位于其内部。状态通过官方 API 更新，正文只维护打卡区块及任务内容区块，保留其他笔记。照片按媒体 ID、完整字节数和校验值去重。服务端分别保存照片校验、记录写入与状态回写，临时失败有限重试。设置中的打卡同步记录可重试、忽略、恢复或重新关联；同一来源的忽略与恢复在设备间共享。明确删除的来源自动归档，未知来源由用户核对。历史记录关联到其他笔记时只写记录和照片，保留目标笔记状态。区块被用户修改时提示处理；服务器图片到期不删除已经同步的本地照片。

命令 **Paca 任务同步：同步任务、打卡记录和照片** 共用自动/手动同步流程，支持启动、恢复前台和定时同步，默认五分钟。另提供“提交当前任务更改”及“选择已有任务接入 Paca”。

## 验证

构建、lint、类型检查、单元测试、包体检查与发布全部通过 GitHub Actions。真实隔离 Obsidian 使用固定官方发行资产和精确 A/C SHA，验证普通任务、直接 MD 编辑、每期笔记、照片及状态回写，以及设置中的清理确认、取消、待处理项移除和本地文件保留。报告区分 Action 与手机真机结果；未经设备测试不宣称手机通过。
